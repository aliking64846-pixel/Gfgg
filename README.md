# مستقبلي 100

موقع دراسة للمنهج العراقي، مصمم للعمل من المتصفح على الهاتف والحاسوب.

## التشغيل والنشر
- الصفحة الرئيسية: `index.html`
- النشر: GitHub Pages عبر GitHub Actions عند كل تحديث على فرع `main`.
- لا يحتاج المشروع إلى تثبيت Node.js أو تشغيل خادم محلي إذا بقي تطبيقاً ثابتاً بملف HTML.

## ملاحظات مهمة
- افتح الموقع من رابط GitHub Pages، وليس من صفحة عرض الكود في GitHub.
- التقدم المحفوظ داخل المتصفح (إن كان التطبيق يستخدم التخزين المحلي) يبقى عادةً على الجهاز والمتصفح نفسه، ولا ينتقل تلقائياً إلى جهاز آخر.
- لا تضع كلمات مرور أو معلومات شخصية حساسة في بيانات المتصفح.
- قبل إضافة ميزات جديدة إلى `index.html`، اختبر التنقل والأزرار والحفظ على الهاتف وبعد تحديث الصفحة.

## بنية المستودع
- `index.html`: التطبيق الرئيسي.
- `.github/workflows/pages.yml`: نشر الموقع على GitHub Pages.
- `404.html`: صفحة مساعدة عند فتح رابط غير موجود.

# CyberGuard — لوحة الأمن السيبراني

أُضيفت واجهة CyberGuard إلى `index.html`، وأُضيف خادم Node.js اختياري في `server.js` مع إعدادات `package.json`.

## تشغيل نسخة API
1. ثبّت Node.js 18 أو أحدث.
2. نفّذ `npm install` داخل مجلد المشروع.
3. شغّل `npm start`.
4. افتح `http://localhost:3000`.

## نقاط API
- `GET /api/health` — حالة الخدمة.
- `POST /api/analyze-logs` — تحليل أولي لنص السجلات. أرسل JSON بالشكل `{"logs":"login failed\\nwarning invalid token"}`.

## النشر
GitHub Pages يستضيف ملفات ثابتة فقط ولا يشغّل `server.js`. لتفعيل API يجب نشر المشروع على خدمة تدعم Node.js (مثل Railway أو Render) باستخدام `npm start`. لا يُعد الخادم منشوراً لمجرد رفع الملفات إلى GitHub.

## حدود الأمان
- إحصائيات وتنبيهات لوحة العرض تجريبية.
- تحليل السجلات مطابقة نصية أولية، وقد ينتج نتائج خاطئة أو يفوّت أحداثاً.
- لا يوجد فحص تلقائي حقيقي للأجهزة أو الشبكات أو اتصال بأنظمة SIEM/EDR.
- لا ترفع كلمات مرور أو مفاتيح سرية أو سجلات حساسة إلى مستودع عام.
- اختبر فقط الأنظمة التي تملكها أو لديك إذن صريح لاختبارها.
